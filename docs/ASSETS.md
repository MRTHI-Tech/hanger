# Screenshots, and where they go

All eight images the README uses are in `docs/assets/` and wired up. Nothing is
outstanding. This file is the record of what each one is, so a replacement can
be dropped in later without guessing.

---

## The eight in use

| Filename | What it is |
|---|---|
| `hero.png` | The finished outfit. The composite image of the three pieces worn together, with the shopping list beside it: R799, R419.40, R999 and the total |
| `hanger.png` | Your Hanger with the three garments, each showing its shop and price: zara.com, bash.com, superbalist.com |
| `outfit-builder.png` | The Build an outfit screen, with the Top, Layer, Bottom and Shoes slots filled from three different shops |
| `alternatives.png` | The Bash Nike sneaker at R2,199.95, with five cheaper versions found elsewhere and how much each one saves |
| `tryon.png` | The panel on the Superbalist blouse page, in pink, showing the row of the page's photos and the guess at what the garment is |
| `two-shops.png` | The two angled windows, Superbalist and Bash, each with a Hanger panel open |
| `phone.png` | The three phone screens: the three ways to add something, the guide to photographing a garment, and naming the leather jacket shot on a shop rail |
| `pairing.png` | The pairing screen with the six characters, the QR code, and the phones already connected |

Replacing one means overwriting the file. The names are what the README points
at, so a new file under an old name needs no edit anywhere.

---

## Two things to check before publishing

**The pairing codes are visible** in `pairing.png` and, if you ever add it, in
the phone's own connect screen. They expire, so this is close to harmless, but
generating a fresh one after publishing costs nothing.

**Your email address** appears in the phone's "Signed in as" card. That screen is
deliberately not used in the README for that reason. Your address is already in
the repo's commit history, so it isn't a new exposure, but there's no reason to
put it on the front page.

## Not used, and not needed

Four things were sketched out earlier and are no longer referenced anywhere, so
you don't have to shoot them:

- The `chrome://extensions` install screen. The written steps are clear enough.
- A sample-mode result. The README says in words that samples are drawings, and
  the point of the screenshots is to show the real thing.
- A close crop of the button on a shop page. It's visible at the bottom right of
  nearly every screenshot already.
- The three accent colours side by side. The screenshots happen to cover two of
  the three, blue and pink, which makes the point without a dedicated image.

Every feature the README claims now has a picture behind it.

## For the submission gallery

The submission form has its own gallery, separate from the README.

**Cover image, 1200 by 630.** Use `hero.png` cropped to that shape. It's the
strongest single frame you have.

**Gallery order.** They show in the order you upload, so lead with the payoff:

1. `hero.png`, the outfit
2. `hanger.png`, three shops in one place
3. `outfit-builder.png`, how it was assembled
4. `alternatives.png`, the same shoe for R660 less
5. `two-shops.png`, the same thing on two different sites
6. `phone.png`, the phone
7. `tryon.png`, reading a product page
8. `pairing.png`

**Captions matter**, because a judge scrolling the gallery may never open the
repo. One line each, and make the first one say the thing outright: *"One image.
A top from one shop, trousers from another, shoes from a third."*
